# Exporting

Every finished result can be saved in six ways. Open the dialog with **File → Export...**, **Ctrl+E**, or the **Export...** buttons of the single-file card and of the list toolbar. The command is available as soon as at least one file is finished (files that failed or were cancelled are never exported).

## The export dialog

- Choose one of **Text (TXT)**, **CSV**, **JSON**, **Excel (XLSX)**, **Word (DOCX)** or **Checksum file**. For the checksum file you also pick the **algorithm** (only algorithms that were actually computed are offered).
- If some rows are selected, a checkbox **Selected files only (n)** appears and is ticked by default.
- A native *Save* dialog proposes a name and remembers the last format and folder (stored in [[Settings]]). With one file the name is `<file>.hasher.<ext>`, with several `hasher-YYYYMMDD-HHMMSS.<ext>`; checksum files are `<file>.<ext>` for one file and `checksums.<ext>` otherwise. A toast confirms: *Exported to report.csv*.

**What goes into the file**

- The **algorithms** that are currently active (those shown as hash rows) and were computed for the file, in the usual order (CRC32 first, ED2K last). A missing digest is written as *n/a* (or `null` in JSON).
- Hexadecimal **case** follows *Uppercase hexadecimal* in Settings (SFV is always uppercase).
- **Labels** (column titles, "Generated by", "Date"...) follow the interface language, and dates use that language's format (`2026-10-09 14:30:00` in English, `09/10/2026 14:30:00` in Italian). JSON keys and JSON dates are language-independent.
- Every format except CSV records the generator signature `Hasher <version> — Martini Multimedia s.a.s.` and the generation date (CSV is a pure data table).

| Format | Extension | Best for |
|---|---|---|
| Text | `.txt` | Reading, mailing, pasting in a ticket |
| CSV | `.csv` | Spreadsheets, scripts that want a flat table |
| JSON | `.json` | Programs and automation |
| Excel | `.xlsx` | A formatted, filterable spreadsheet |
| Word | `.docx` | A report to print or attach |
| Checksum file | `.sha256`, `.md5`, `.sfv`... | Verifying the files again later |

## TXT

A UTF-8 report with `\n` line endings: a header, then one block per file with aligned `label : value` lines, then one line per hash (names aligned), and a footer with the signature. *Attributes* and *Permissions* lines are omitted when empty.

```text
Hash report
===========
Generated by: Hasher 0.1.0 — Martini Multimedia s.a.s.
Date: 2026-10-09 14:30:00
Number of files: 1
------------------------------------------------------------------------

File        : abc.txt
Path        : /data/docs/abc.txt
Size        : 1.23 MB
Size (bytes): 1234567
Created     : 2026-01-02 12:04:05
Modified    : 2026-03-04 12:05:06
Attributes  : R
Permissions : rw-r--r--

CRC32  : 352441c2
MD5    : 900150983cd24fb0d6963f7d28e17f72
SHA-256: ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad

------------------------------------------------------------------------
Hasher 0.1.0 — Martini Multimedia s.a.s.
```

## CSV

- **UTF-8 with a byte order mark (BOM)**, so Excel opens accents correctly; **comma** separator; **CRLF** line endings (RFC 4180 quoting).
- Columns: `File, Path, Size (bytes), Size, Created, Modified, Attributes, Permissions`, then one column per algorithm named after it (`CRC32, MD5, SHA-256...`).
- **Spreadsheet formula protection**: a *File* or *Path* value that starts with `=`, `+`, `-`, `@`, a tab or a carriage return is prefixed with an apostrophe (`'`), following OWASP guidance, so Excel or Calc never evaluates a hostile file name as a formula. The apostrophe is part of the text: a file named `-notes.txt` appears as `'-notes.txt`.
- *Size (bytes)* is the exact number, *Size* the human-readable base-10 value.

## JSON

Pretty-printed UTF-8. Keys are fixed English names, dates are RFC 3339, hash keys are the algorithm ids (`crc32`, `sha256`, `sha3-256`, `blake2b-512`, `xxh3-128`, `ed2k`...) in output order, missing values are `null`.

```json
{
  "app": { "name": "Hasher", "version": "0.1.0", "company": "Martini Multimedia s.a.s." },
  "generated_at": "2026-10-09T14:30:00+02:00",
  "files": [
    {
      "name": "abc.txt",
      "path": "/data/docs/abc.txt",
      "size": 1234567,
      "size_human": "1.23 MB",
      "created": "2026-01-02T12:04:05+01:00",
      "modified": "2026-03-04T12:05:06+01:00",
      "accessed": "2026-05-06T12:06:07+02:00",
      "attributes": ["read_only", "hidden"],
      "permissions": "rw-r--r--",
      "hashes": {
        "crc32": "352441c2",
        "md5": "900150983cd24fb0d6963f7d28e17f72",
        "sha256": "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"
      }
    }
  ]
}
```

`attributes` uses the ids `read_only`, `hidden`, `system`, `archive`, `compressed`, `encrypted`, `temporary`, `sparse`, `offline`, `not_indexed`, `reparse_point`, `symlink`, `executable`, `setuid`, `setgid`, `sticky`. `permissions` is `null` on Windows.

## XLSX

Opens in Excel and LibreOffice Calc; it replaces the legacy `.xls`.

- **Sheet "Hashes"**: the same columns as the CSV. The header row is bold white text on the brand blue (`#144781`) and is **frozen**; an **autofilter** covers the whole table. *Size (bytes)* is a real number formatted `#,##0`; hashes use the **Consolas** font and columns are sized from the digest length (16 to 70 characters wide).
- **Sheet "Info"**: the report title, generator, date, number of files and the list of algorithms.
- Every value is stored as text, never as a formula, so a file named `=SUM(A1)` stays harmless without any prefix.
- Document properties: title, author and company are set.

## DOCX

Opens in Word and LibreOffice Writer; it replaces the legacy `.doc`. A4 page with 2 cm margins.

- A blue title (*Hash report*) and three metadata lines (*Generated by*, *Date*, *Number of files*).
- **One section per file**: the file name as a heading, a two-column table with *Path, Size, Size (bytes), Created, Modified* (and *Attributes*, *Permissions* when present) on a light-blue label column, then an **Algorithm / Hash** table with a blue header row and the hashes in **Consolas 9 pt**.
- Every file after the first **starts on a new page**.
- A final italic line with the generator signature.

## Checksum files

The checksum export writes **one algorithm** per file in the format that other tools understand:

```text
# Hasher 0.1.0 — Martini Multimedia s.a.s.
# Date: 2026-10-09 14:30:00
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad  abc.txt
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855  empty.bin
```

- **GNU format** (`hash`, two spaces, name) with `#` comments. Names that contain a backslash or a line break use the coreutils escaping convention (line prefixed with `\`). Case follows the *Uppercase hexadecimal* setting.
- For **CRC32** the file is an **SFV**: `; ` comments, `name CRC` with an *uppercase* CRC32.

```text
; Hasher 0.1.0 — Martini Multimedia s.a.s.
; Date: 2026-10-09 14:30:00
abc.txt 352441C2
```

- The extension follows the algorithm: `.sfv` (CRC32), `.md5`, `.sha1`, `.sha256`, `.sha512`, `.b2` (BLAKE2b-512), `.blake3`. Any other algorithm (SHA-224, SHA3, RIPEMD...) is saved as `.txt`.
- Files that lack the chosen algorithm are skipped and counted in a closing comment (`# MD5 n/a: 1`).
- Only the **file name** is written, not the path. Save the checksum file in the same folder as the files, and export one folder at a time, so that names stay unique.
- **Reuse**: drop the file onto Hasher ([[Verifying Hashes]]) or run `sha256sum -c file.sha256` / `md5sum -c file.md5` in that folder; GNU tools ignore the `#` lines. Hasher only treats certain extensions as checksum files (see [[Verifying Hashes]]), so rename a `.txt` export to `.hash`, `.sum` or `.sha3` before dropping it.
